# Review Checks (Learned)

- **Reconcile secondary ledgers when closing stale plan items** (2026-05-17): When reviewing a stale-plan closure, verify roadmap/status docs do not still list the same idea id as open because future loops can rediscover it as active work. [workflow: improvement-plan-loop]
- **Close completed umbrella parents from shipped child evidence** (2026-05-17): Before selecting an active umbrella item, compare its proposed changes against shipped child slice ids in `docs/*-done.md`; if all value-bearing children are already complete, close the parent with evidence rather than executing it again. [workflow: improvement-plan-loop]
- **Split prompt behavior from lint-tooling scope** (2026-05-17): When reviewing prompt-improvement plan closures, verify user-visible prompt behavior and generic future lint tooling are not collapsed into one done claim unless both shipped. [workflow: improvement-plan-loop]
- **Require backing for JSON prompt contracts** (2026-05-17): Every MAP skill prompt section containing `Output JSON with:` must either put evidence/quotes before judgment fields or cite `.claude/references/map-json-output-contracts.md`; do not accept unsupported verdict, risk, score, or summary JSON surfaces. [workflow: improvement-plan-loop]
- **Trace coverage_map keys into validation criteria** (2026-05-18): When reviewing blueprint/decomposer changes, always verify every `coverage_map` key appears as a bracketed tag in the owning subtask's `validation_criteria` because ownership without an executable criterion still lets requirements disappear before review. [workflow: improvement-plan-loop]
- **Keep blueprint schema gates end-to-end** (2026-05-18): When adding blueprint fields that prompts must emit, verify schema, validator semantics, Claude and Codex planner/decomposer surfaces, examples, template copies, docs, and generated-project pass/fail smokes all changed together. [workflow: improvement-plan-loop]
- **Review acceptance coverage as downstream evidence** (2026-05-18): A `coverage_map` key should be counted as covered only when its bracketed tag appears in downstream verification, QA, test, handoff, PR draft, or review artifacts; do not let planning-time validation criteria alone satisfy review/verification coverage. [workflow: improvement-plan-loop]
- **Warn on missing prior-stage inputs in review bundles** (2026-05-18): Review bundle generation should remain available for diagnosis, but the review manifest should downgrade to `warn` when required prior-stage inputs are missing so stage skipping is visible. [workflow: improvement-plan-loop]
- **Constrain parallelism wording to real dependency boundaries** (2026-05-18): When reviewing MAP skill prompt edits, verify `parallel_tool_policy` does not permit parallel state transitions, shared artifact writes, or same-subtask Actor/Monitor/test-gate phases; fan-out should be limited to independent reads/checks or explicitly supported wave/reviewer APIs. [workflow: improvement-plan-loop]
- **Preserve real gates while reducing prompt force** (2026-05-18): When reviewing prompt-tone changes, verify hard workflow gates such as Monitor validation, state-machine updates, TDD test immutability, and release/tag confirmation still read as required behavior even after removing all-caps CRITICAL/MUST wording. [workflow: improvement-plan-loop]
- **Preserve artifact-first prompt envelopes** (2026-05-19): When reviewing high-context MAP skill prompt edits, verify long artifacts stay in `<documents>` before instructions and that `/map-review` keeps the review bundle primary while treating the raw diff as secondary. [workflow: improvement-plan-loop]
- **Allow bundled reference links in Skill IR audits** (2026-05-19): When reviewing skill-surface link audits, verify relative Markdown links may resolve anywhere inside the provider bundle root, not only inside one skill folder, because MAP skills intentionally link to shared `references/*.md` files. [workflow: improvement-plan-loop]
- **Close targeted-mode implementations of broad workflow ideas** (2026-05-19): Before implementing a broad workflow-mode active item, inspect whether the highest-payoff targeted mode already ships the promised user journey in runtime code, shipped templates, docs, roadmap, and focused tests; if yes, close the stale parent with evidence instead of rebuilding it. [workflow: improvement-plan-loop]
- **Prioritize active-task evidence in prompt budget reviews** (2026-05-19): When reviewing budgeted prompt context builders, verify truncation removes broad overview or low-priority artifact text before current-subtask identity, dependency status, validation criteria, and closing envelope markers. [workflow: improvement-plan-loop]
- **A/B prompt budgets against the old unbounded prompt** (2026-05-19): When reviewing prompt-budget changes, require an old/new comparison that proves the old prompt exceeds the target while the new prompt stays under budget and preserves task, instruction, expected-output, and primary artifact sections. [workflow: improvement-plan-loop]
- **Review Budget Artifacts For Actionability** (2026-05-20): When reviewing prompt-budget artifacts, always verify each decision names the prompt path, before/after estimates, clipped sections, source artifacts, and adjustment knob because raw token counts alone do not tell operators whether to continue, raise a budget, or split the workflow. [workflow: improvement-plan-loop]
- **Check supporting-file externalization end to end** (2026-05-20): When low-frequency skill content moves out of `SKILL.md`, verify the active workflow still names the next action, Markdown links resolve, non-SKILL supporting files are template-synced, and generated installs include both files. [workflow: improvement-plan-loop]
- **Review compacted skills for live workflow markers** (2026-05-20): When reviewing skill-body compaction, always verify state-machine commands, prompt envelope links, run-health writes, review bundle wiring, and handoff artifacts remain in active `SKILL.md` because supporting files should not hide mandatory execution gates. [workflow: improvement-plan-loop]
- **Require mutation boundaries near direct-edit prompts** (2026-05-20): When reviewing any prompt that tells Actor, a fix phase, or Codex `$map-fast` to edit files directly, verify it also blocks unrelated files, dependency changes, and neighboring refactors unless the current contract explicitly requires them, with required scope expansion reported as a blocker/tradeoff. [workflow: improvement-plan-loop]
- **Keep clean retry as a behavior gate** (2026-05-20): A clean retry change must force the next Actor attempt to read `retry_quarantine.json`; counters or run-health fields alone are not enough unless the workflow prompt/state machine changes the retry context. [workflow: improvement-plan-loop]

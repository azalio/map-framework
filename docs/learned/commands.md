# Command Patterns (Learned)

<!-- IMPROVEMENT-PLAN-LOOP: promoted from loop learnings. Edit freely and commit with the project. -->

- **Use repo-built init for template verification** (2026-04-13): When validating shipped MAP templates, always run `uv run mapify init <new-dir> --no-git --mcp none` because the globally installed `mapify` binary may still reflect an older release instead of the branch you are reviewing. [workflow: improvement-plan-loop]
- **Use non-existent target paths for init smoke tests** (2026-05-15): `mapify init <path>` creates the target directory, so do not pre-create it with `mktemp -d`; pass a unique path under an existing temp parent and then inspect the generated `.claude/` artifacts. [workflow: improvement-plan-loop]
- **Grep stale skill names during taxonomy changes** (2026-05-15): When skill catalog docs change, search for removed or non-shipped skill names such as `map-workflows-guide` and `map-cli-reference`; generated install smoke tests prove current templates emit metadata, but they do not catch every stale prose reference. [workflow: improvement-plan-loop]
- **Validate run health reports in CI handoff** (2026-05-16): Use `python3 .map/scripts/map_step_runner.py validate_run_health_report [path]` after `write_run_health_report` when a workflow closeout must fail on schema drift, retry overflow, missing verification evidence, or unexplained hook degradation. [workflow: improvement-plan-loop]
- **Close already-shipped active ideas with repo evidence** (2026-05-16): Before implementing an active improvement-plan item, inspect active and done headings, then search runtime, shipped templates, docs, and tests for the core artifact or route names; if the capability already exists, move the exact `[idea_id]` to done with evidence instead of rebuilding it. [workflow: improvement-plan-loop]
- **Check both skill and helper surfaces before review-workflow work** (2026-05-17): For `/map-review` backlog items, inspect `.claude/skills/map-review/SKILL.md`, the shipped template copy, `.map/scripts/map_step_runner.py`, docs, roadmap status, and focused tests before implementation; review capabilities can be split across prompt wiring and helper scripts. [workflow: improvement-plan-loop]
- **Smoke generated evidence references** (2026-05-17): When shipped skill prompts link to new shared references, run `uv run --no-sync mapify init <new-dir> --no-git --mcp none` and inspect generated `.claude/references/` plus the generated skill links because source-template sync alone does not prove installed output. [workflow: improvement-plan-loop]
- **Run JSON prompt-contract guardrails** (2026-05-17): When changing MAP skill prompts that contain `Output JSON with:`, run `pytest tests/test_skills.py::TestEvidenceFirstPromptContracts tests/test_template_sync.py -v` so vague JSON contracts fail in both source and shipped template surfaces. [workflow: improvement-plan-loop]
- **Validate blueprint lineage in generated projects** (2026-05-18): When changing blueprint validator semantics, run `uv run --no-sync mapify init <new-dir> --no-git --mcp none` and exercise the generated `.map/scripts/map_step_runner.py validate_blueprint_contract` on both passing and failing fixtures because source tests alone do not prove installed projects enforce the new gate. [workflow: improvement-plan-loop]
- **Validate hard/soft blueprint constraints** (2026-05-18): Use `python3 .map/scripts/map_step_runner.py validate_blueprint_contract <path-to-blueprint.json>` to fail MAP plans where a hard constraint is not in `coverage_map` or an uncovered soft constraint lacks `tradeoff_rationale`. [workflow: improvement-plan-loop]
- **Report acceptance coverage from branch artifacts** (2026-05-18): Use `python3 .map/scripts/map_step_runner.py build_acceptance_coverage_report` to inspect which `coverage_map` tags have downstream evidence before final review or verification handoff. [workflow: improvement-plan-loop]

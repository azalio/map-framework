# MAP Framework Roadmap

Reviewed: 2026-05-11.

This roadmap is a status-based version of the original roadmap. It keeps the
useful product ideas from [improvement-plan](./improvement-plan.md), but marks
what is already shipped and re-scopes old command-file work to the current
skill-backed MAP surface.

It is based on:

- [Improvement Plan](./improvement-plan.md) - source ideas and rationale
- [Improvement Done](./improvement-done.md) - shipped slices
- [Architecture](./ARCHITECTURE.md) - current system model
- [Usage](./USAGE.md) - current user-facing workflow
- [MAP philosophy / DevOpsConf draft](./devopsconf_2026_ai_operator_presentation_rewrite-v2.md) - target process: `SPEC -> PLAN -> TEST -> CODE -> REVIEW -> LEARN`

## Fixed Product Decisions

- For non-trivial tasks, MAP should require `SPEC + PLAN` before implementation.
- For serious changes, `REVIEW` remains a mandatory stage.
- `LEARN` is part of the MAP philosophy, but it stays a soft runtime step because users optimize for token cost.
- Trivial tasks need an explicit off-ramp: not every change should trigger MAP orchestration.
- Runtime contracts come before prompt polish. Do not try to fix process drift with wording alone.
- MAP slash surfaces are skill-backed. Do not reintroduce `map-*.md` command files under `.claude/commands/` or `src/mapify_cli/templates/commands/`.

## Current Status

### Shipped Runtime Alignment

The old "Iteration 1" is mostly complete:

- `/map-plan` records a workflow-fit decision and can off-ramp trivial work.
- `.map/<branch>/artifact_manifest.json` exists as the high-level stage ledger.
- Targeted TDD writes `test_contract_ST-00N.md` and `test_handoff_ST-00N.json`.
- `/map-task ST-00N` can resume implementation from the persisted TDD contract.
- `learning-handoff.md` / `.json` preserves context for deferred `/map-learn`.
- Learning metrics and repeated learned-rule violation tracking exist.
- `run_health_report.json` records terminal status, retry counters, artifact presence, latest hook-injection status, and auditable skipped hook reasons for diagnosis and resume handoff.

Useful follow-up from that iteration:

- Finish hard/soft constraint typing and acceptance-criteria lineage on top of the shipped subtask guardrail gate.
- Keep review-bundle and detached-review tests around the shipped review contract.
- Keep tests around all artifact contracts.

### Shipped Skill Consolidation

The roadmap's old command/skill drift diagnosis was correct, but the repo has
since moved further toward skill-backed slash surfaces:

- `/map-learn` is skill-first.
- MAP command files under `src/mapify_cli/templates/commands/map-*.md` should not return.
- `skill-rules.json` classifies each shipped skill as `task`, `reference`, or `hybrid`; `map-state` is the only current hybrid because it also declares hook/script runtime effects.
- `tests/test_template_render.py` enforces that generated template trees match the `.jinja` sources.

The practical implication: future roadmap items should point at
`src/mapify_cli/templates/skills/map-*/SKILL.md` and, where applicable,
`src/mapify_cli/templates/codex/skills/`, not old command files.

review contract that did not primarily rely on implementer session context.

## Next Iteration 2: Contract-Sized Subtask Guardrails

**Status:** first runtime slice shipped.

**Why this matters:** MAP planning is only useful if subtasks stay small enough
to review and execute. The current workflow records `expected_diff_size` at the
workflow-fit level, but the subtask contract still needs stronger shape.

**Improvement-plan item:** `2604.039`.

### Shipped Scope

- `/map-plan` and `/map-efficient` require per-subtask `expected_diff_size`, `concern_type`, `one_logical_step`, AAG, validation criteria, and top-level `coverage_map` metadata.
- `validate_blueprint_contract` fails empty, oversized, mixed-concern, untraceable, or non-logical-step blueprints before implementation starts.
- `verification-summary.md` and `review-bundle.*` report whether each `coverage_map` tag has downstream evidence in verification, QA, test, PR draft, handoff, or review artifacts.
- Actor context, Monitor, and FinalVerifier now receive or check the subtask contract metadata so scope creep remains visible after planning.

### Remaining Follow-up

- Add explicit prior-stage artifact consumption gates so implementation and review closeout record which spec, blueprint, test, and diff artifacts they consumed.
- Continue propagating durable acceptance-criteria IDs into generated test contracts where workflows still omit tags.

## Later Iteration: Orchestrator R&D And Deep Optimization

**Status:** deferred.

**Improvement-plan items:** `2604.019`, `2604.020`, `2604.021`, `2604.022`, `2604.023` (Actor context-budget slice shipped as `2604.023-1`; reviewer prompt-budget slice shipped as `2604.023-2`), `2604.024`, `2604.014`, `2604.017`.

### Scope

- `REGISTRY/FOCUS`
- steering requests and preemption
- deterministic token budgets beyond the shipped Actor and review prompt caps
- agent registry snapshots
- multi-phase evaluation harness
- family-specific model scaling analysis
- deeper resiliency and health reporting

### Decision Rule

Do not start this work until subtask-size guardrails have clear artifacts and
tests. Review independence now has shipped review-bundle and detached-review
artifacts; advanced orchestration ideas are useful only if they are measured.

### Exit Criteria

- Advanced orchestration ideas are feature-flagged.
- Evaluation compares approval rate, latency, token/context discipline, and review quality.
- MAP can prove which mechanisms improve outcomes.

## What Not To Do First

- Do not start with `REGISTRY/FOCUS` while subtask guardrails are still open.
- Do not reintroduce `.claude/commands/map-*.md` or `src/mapify_cli/templates/commands/map-*.md`.
- Do not try to "fix MAP" only through wording changes in prompts.
- Do not make `LEARN` hard-gated.
- Do not treat prompt modernization as more important than runtime artifacts.

## Practical Execution Notes

- If `.claude/skills/`, `.claude/hooks/`, or shared templates change, keep them synchronized with `src/mapify_cli/templates/`.
- Preferred render path: `make render-templates` (propagates `.jinja` sources to all generated trees).
- MAP slash surfaces should live under `src/mapify_cli/templates/skills/map-*/SKILL.md`.
- Codex-specific behavior should be mirrored under `src/mapify_cli/templates/codex/skills/` only where the Codex provider supports that surface.
- Keep `tests/test_template_render.py` green; it enforces byte-identity between templates_src renders and committed generated trees.
- For runtime/artifact changes, add focused tests next to:
  - [tests/test_map_orchestrator.py](../tests/test_map_orchestrator.py)
  - [tests/test_map_step_runner.py](../tests/test_map_step_runner.py)

## Short Version

The useful roadmap is now:

1. Keep the shipped workflow-fit, artifact-manifest, TDD handoff, and learning-handoff contracts stable.
2. Keep the shipped review bundle and detached review path stable.
3. Finish contract-sized subtask guardrails.
4. Modernize skill-backed prompts, not obsolete command files.
5. Clean up skill taxonomy and triggers.
6. Only then invest in advanced orchestration R&D.
